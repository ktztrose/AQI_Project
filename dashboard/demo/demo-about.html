What this system does

This is a low-cost AIoT air quality monitoring node built around an ESP32 microcontroller and four sensors. It continuously measures particulate matter, carbon monoxide, and ammonia, computes a composite Air Quality Index (AQI), and displays it live — with alerts triggered both on the device itself and on this dashboard.

It was built to address a real gap: many rapidly urbanizing cities across India and Myanmar have very few official air quality monitoring stations, and existing systems rarely offer real-time analytics or predictive capability. This project demonstrates that a low-cost sensor node can still produce a methodologically sound, standards-aligned AQI reading.

How the AQI is calculated

Each pollutant reading is converted into a sub-index between 0 and 500, using the Central Pollution Control Board's (CPCB) official breakpoint tables and linear interpolation formula — the same methodology used by India's government monitoring stations.

The final AQI reported is the highest of the four sub-indices, not an average — consistent with CPCB's own rule that overall air quality is defined by whichever pollutant is currently most concerning.

Scope — what's measured, and what isn't

CPCB's official AQI standard uses eight pollutants: PM2.5, PM10, NO2, SO2, CO, O3, NH3, and Pb. This system measures four of them.

In scope

  • PM2.5
  • PM10
  • Carbon monoxide (CO)
  • Ammonia (NH3)

Not measured

  • Nitrogen dioxide (NO2)
  • Sulfur dioxide (SO2)
  • Ozone (O3)
  • Lead (Pb)

This isn't an oversight — electrochemical sensors capable of measuring NO2, SO2, and O3 accurately cost significantly more than the sensors used here, which would undermine the goal of a genuinely low-cost, replicable system. CPCB's own methodology only requires a minimum of 3 pollutants (including one particulate measurement) for a valid composite AQI — a requirement this system satisfies.

The reading shown here should be understood as a composite AQI derived from available low-cost sensor data, not a claim of full regulatory equivalence.

System architecture

Sensor readings are taken by the ESP32 every 60 seconds, published over MQTT to a broker, picked up by a Python backend that stores them in a database and serves them through a REST API, which this dashboard polls every 30 seconds to stay current.

Sensors → ESP32 → MQTT broker → Backend (Flask + SQLite) → Dashboard
